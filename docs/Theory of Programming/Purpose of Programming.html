Purpose of Programming

What is Programming?

At its core, programming is not just about writing code or memorising syntax. Programming is the process of instructing a computer to solve a specific problem or automate a repetitive task.

Computers are incredibly fast at arithmetic, but they have zero intuition. They require explicit, logical, step-by-step instructions to do anything useful.

What is an algorithm?

An algorithm is a finite sequence of well-defined steps for solving a problem. In other words, it is a recipe that a computer can follow exactly.

In statistics and data science, algorithms are used for:

  • cleaning and preparing data,
  • computing summaries and statistics,
  • fitting models,
  • running simulations,
  • validating results.

This is why programming theory matters: it teaches you how to build the logic behind every statistical task, not just how to type code.

Why Learn to Program in Statistics?

As a statistician or data scientist, programming serves three primary purposes:

  1. Automation: Running an analysis on 5 data points by hand is easy. Running it on 5,000,000 data points requires automation.
  2. Reproducibility: If you compute a test statistic by clicking buttons in Excel, no one can easily replicate your steps. A script records your exact logical workflow.
  3. Simulation: When mathematical theory becomes too complex to solve analytically, we use programming to simulate data and approximate answers.

The Core Workflow

Every program you will ever write—whether a simple R script, a Python data pipeline, or a Java application—follows the exact same fundamental mathematical and logical loop:

\[\text{Input Data} \longrightarrow \text{Process (Your Logic)} \longrightarrow \text{Output Result}\]

Example: A Simple R Program

Here is how this operational loop looks inside an R script calculating a basic statistical mean:

# 1. INPUT: Define a vector of student exam scores
scores <- c(72, 85, 64, 91, 78)

# 2. PROCESS: Calculate the average score
avg <- sum(scores) / length(scores)

# 3. OUTPUT: Print the result to the console
print(avg)

Notice how the logic is explicitly split. The computer doesn’t “know” what an average is; we have to tell it to sum the items first, count them second, and divide third. This is how you should think about code which is that an input is taken, a finite set of instructions are executed and then the output is revealed (this is by design the definition of an algorithm).

With the rise of Large Language Models (LLMs), it is tempting to just ask an AI to write your scripts for you. However, relying on AI without understanding the foundation leads to major blind spots:

  1. The Hallucination Trap: LLMs frequently invent R functions or Python libraries that do not exist, or they use outdated syntax that will break your code.
  2. The Logic Gap: An AI can give you a block of code, but if your underlying statistical model or data structure is wrong, the output will be mathematically meaningless (“Garbage In, Garbage Out”).

The Goal of this Course: To teach you how to think like a programmer so you can write, debug, and critique code independently—whether it’s generated by you or an AI.

The statistical programming loop

A useful way to think about code is as a statistical workflow:

  1. Input data,
  2. Process it using algorithms,
  3. Output results and diagnostics.

For example, a typical analysis may look like:

  • load the raw dataset,
  • clean and transform the variables,
  • fit a model or compute a statistic,
  • review the result and check whether it makes sense.

This loop is the same in R, Python, or any other language; the difference is only the vocabulary and syntax.
